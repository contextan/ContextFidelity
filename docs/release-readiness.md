# 출시 준비 보완 체크리스트

이 체크리스트는 영역별 구현·검증 기준이다. 번호와 배열 순서는 우선순위가 아니다.

상태는 현재 코드와 자동 테스트를 기준으로 2026-10-10에 확인했다.

## 상태 표시와 기록

1. **선택·전달·검증 상태 분리 — 구현됨.** 답변 영수증과 검증 기록이 실제 모델 입력과 검증 결과를 따로 표시한다.
2. **결정과 배경 컨텍스트 구분 — 부분 보완됨.** 저장 컨텍스트와 결정은 별도로 기록한다. 목표·역할을 결정으로 추출했을 때 앱이 배경으로 바꾸는 규칙이 있어 UI가 원시 모델 분류와 달라 보일 수 있다. 이번 QA 관찰 이후 사용자 역할·신원 정보도 배경으로 재분류하고, 예전 오분류 역할 결정은 모델에 강제 전달하지 않도록 보완했다. 이 규칙은 자동 테스트에 추가했으며, 활성 사용 데이터는 마이그레이션하지 않았다.
3. **화면 용어 통일 — 보완 필요.** 배경·참고·가설·결정·대화 맥락을 나타내는 문구가 화면마다 조금씩 다르다.
4. **답변 당시 기록과 현재 미리보기 구분 — 구현됨.** 과거 답변 영수증과 다음 답변 후보 미리보기를 구분한다.
5. **포함·제외 이유와 검색 점수 — 구현됨.** 포함·제외 이유, FTS5 점수, 일치 키워드와 원문 링크를 저장·표시한다.

## 컨텍스트와 결정 관리

6. **결정 목록·보관·복원·삭제 — 구현됨.** 결정은 별도 탭에서 관리할 수 있다. 편집 진입점은 없다.
7. **결정 수정과 버전 이력 — 보완 필요.** 저장 계층은 대체 버전을 보존하지만 UI에서 수정하거나 전체 이력을 확인할 수 없다.
8. **모델 가설 검토 — 부분 구현.** 사용자 승인을 기다리고 개별 승인·무시할 수 있지만 일괄 검토는 없다.
9. **유사·중복 컨텍스트 정리 — 보완 필요.** 동일 원문 후보의 중복 삽입은 막지만 의미가 비슷한 항목을 찾아 합치는 기능은 없다.
10. **보관과 영구 삭제 구분 — 구현됨.** 컨텍스트·결정·대화를 각각 삭제하고 전체 저장소를 비울 수 있다. 과거 답변의 고정된 전달 기록은 보존한다.

## 검색과 추출

11. **SQLite FTS5 점수 설명·검색 품질 — 부분 구현.** 코드는 키워드 70%·주제 30%, 기본 기준 50%, 최대 8개를 사용한다. 정확한 기준점 테스트는 있으나 동의어·의역 품질과 최대 8개 상한 테스트는 없다.
12. **분류 결과 검토·수정 — 부분 구현.** 저장 컨텍스트는 종류·내용·범위를 편집할 수 있고 모델 제안은 승인·무시할 수 있다. 제안 검토 중 직접 분류를 고치는 흐름은 없다.
13. **프로젝트 정보 격리 — 구현·테스트됨.** 선택·검색·원문 연결에서 프로젝트 경계를 확인하는 테스트가 있다. 비슷한 이름의 주제가 섞이지 않는 사례 테스트는 더 필요하다.

## 답변 품질

14. **질문 언어에 맞춘 답변 — 구현·단위 테스트됨.** 실사용 모델과 여러 언어가 섞인 대화에서의 일관성은 추가 평가가 필요하다.
15. **요청한 개수·형식 준수 — 구현·단위 테스트됨.** 형식 점검과 1회 교정 흐름이 있다. 실제 모델별 품질은 별도 비교가 필요하다.
16. **불확실한 검증 표시 — 구현·단위 테스트됨.** 근거가 부족하거나 검증에 실패하면 판단 보류로 저장한다.

## 사용성과 운영

17. **답변 완료 후 자동 등록 — 격리 브라우저 재검증됨.** 지연된 자동 추출이 진행 중이고 답변이 보이는 동안 입력창이 활성 상태인 것을 임시 데이터베이스에서 확인했다. 시험용 선택 응답은 형식이 맞지 않아 대체 흐름을 탔으므로, 이 시험은 입력 잠금만 확인했고 컨텍스트 선택 품질은 검증하지 않았다. 기존 QA 기록은 입력이 잠겼다고 관찰했으므로 해당 실행과 사용 모델에서 재확인할 필요는 남는다.
18. **빈 메시지 전송 방지 — 구현됨.** 입력이 비었거나 공백뿐이면 전송 버튼을 비활성화한다.
19. **제목 없는 대화 구분 — 부분 구현.** 첫 사용자 메시지로 제목을 만들지만, 메시지가 없는 새 대화는 같은 이름으로 보여 구분하기 어렵다.
20. **보존 기간 설정 — 미구현.** 개별·전체 삭제는 있지만 일정 기간이 지난 데이터를 자동 정리하는 설정은 없다.

## 검증 범위 메모

- 프로젝트 경계, 결정 대체, 정확히 50%인 점수 경계, 제공자 오류 기록, 백그라운드 등록은 자동 테스트에 포함된다.
- 최대 8개 선택 상한, 동의어·의역 검색, 비슷한 주제명 간 혼동, 실제 모델에서의 다국어·형식 준수 편차는 더 검증해야 한다.
- API 실패는 실패한 입력과 진단을 보존한다. 자동 재시도 정책은 구현·검증된 동작으로 간주하지 않는다.
- 공개 데모의 보존 기간과 방문자 저장소 만료는 별도 운영 정책이 필요하다.

## 추가 QA 관찰

- 같은 프로젝트 안의 다른 테스트에서 나온 사용자 역할 결정이 새로운 QA 대화에 들어간 사례가 보고됐다. `나는 이 프로젝트에서 사용자 인터뷰 담당이야`를 모델이 project decision으로 반환하는 회귀 사례를 추가했고, 앱이 이를 topic background로 바꾸며 예전 역할 문구가 결정 입력으로 강제되지 않는지 확인한다.
- 재현 목표 문장이 model decision에서 Background로 보인 것은 목표 표현을 확정 규칙으로 보지 않는 앱의 재분류 때문이다. Background 항목 설명을 추가해 이 차이를 화면에서 알 수 있게 했다.
- 불확실 판정의 원인은 삭제된 QA 기록만으로 확정할 수 없다. 현재 검증기는 등록된 활성 결정의 원문을 대조하며, 현재 질문의 목표·배경을 결정 원문처럼 취급하지 않는다. 무관한 역할 결정이 들어간 상황과 해당 불확실 판정을 같은 입력으로 다시 재현해 분리 검증해야 한다.
- 브라우저 테스트와 변경은 임시 저장소에서만 수행했다. 사용자가 보존 요청한 대화와 활성 컨텍스트는 수정하지 않았다.
- 최종 확인: `npm test` 83개 통과, `npm run build` 성공, `git diff --check` 오류 없음. 전체 브라우저 재현은 선택 단계가 시험용 응답 오류로 대체된 범위까지로 제한된다.
