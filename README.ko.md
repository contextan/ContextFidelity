# ContextPulse

질문마다 필요한 컨텍스트를 자동으로 선택하고, 모델에 실제로 전달한 내용을 답변별로 보여주는 로컬 웹 채팅 프로토타입입니다. 메뉴를 채팅·컨텍스트 관리·답변 기록·설정으로 정리하고, 대화에 필요한 정보 선택과 실제 입력 기록에 집중했습니다.

현재 제품 범위와 심사 데모 흐름은 [프로젝트 정리 문서](docs/project-summary.md)에서 확인할 수 있습니다.
Colosseum 제출 항목과 공개 전 체크리스트는 [제출 준비 문서](docs/submission-readiness.md)에 정리했습니다.

## 실행

Node.js 24 이상에서 실행합니다. 실행 시 외부 패키지 설치가 필요하지 않습니다. 생성된 스타일 파일을 포함합니다.

```sh
npm start
```

브라우저에서 <http://127.0.0.1:8899>를 엽니다. 서버는 `127.0.0.1`에만 바인딩됩니다.

포트 또는 저장 위치를 변경할 수 있습니다.

```sh
CONTEXTPULSE_PORT=8900 CONTEXTPULSE_DATA_DIR=./my-data npm start
```

앱 종료는 실행한 터미널에서 Ctrl+C를 누릅니다. 다시 실행하면 저장한 대화·컨텍스트·호출 기록을 불러옵니다.

## 첫 사용

1. **교정 흐름 시연**을 누르면 별도 프로젝트에 대화 맥락과 어긋난 초안, 원문 확인, 교정, 재검증 기록을 만듭니다. 실제 모델 호출은 없습니다.
2. **설정**에서 실제 연결 방식을 선택합니다.
3. **프로젝트 채팅**에서 메시지만 보냅니다. 에이전트가 주제와 필요한 컨텍스트를 자동으로 판단합니다.
4. **컨텍스트 관리**에서 배경 정보·참고 자료·검토 중인 가설을 등록하고 주제·범위·포함 방식을 지정합니다. 대화에서 파악한 내용은 자동 등록 이력에서 확인할 수 있습니다.
5. 사용자 발화와 모델 답변에서 맥락을 자동 등록합니다. 저장 버튼을 누를 필요가 없습니다. 원문과 추출 입력·결과를 확인하고 필요하면 컨텍스트를 편집·보관합니다.
6. 채팅 우측에서 최근 답변에 실제 사용한 맥락과 자동 선택 결과를 확인합니다. 대화별 포함·제외 선택은 저장됩니다.
7. 답변별 영수증에서 자동 주제, 저장 맥락, 대화에서 파악한 내용, 이전 대화와 원문을 확인합니다.
8. 답변의 **교정 과정·컨텍스트 보기**에서 각 호출의 입력·결과·출처·RAW를 확인합니다. **입력 차이 비교**로 초안/교정 또는 이전 답변의 호출을 비교할 수 있습니다.

## 자동 컨텍스트 관리

설정의 **대화 맥락 자동 등록·질문별 의미 선택**은 기본적으로 켜져 있습니다. 실제 모델 연결 시 다음 흐름을 사용합니다.

1. 질문과 저장된 컨텍스트의 내용을 별도 모델 호출로 비교해 주제와 포함·제외 이유를 만듭니다. 직접 포함·제외한 선택과 항상 포함 항목은 유지합니다. 이전 대화의 자동 분류 기록을 이용해 관련 발화만 이어받습니다.
2. 선택 결과로 답변 입력을 구성하고 기존 생성·검증·교정 흐름을 수행합니다.
3. 질문 분석 단계에서 현재 질문에 포함된 유용한 맥락을 원문 검증 후 자동 등록해 현재 답변에 적용합니다. 답변 후 최근 대화 최대 8턴에서 사용자 맥락과 모델 제안을 추가 등록합니다. 모델 제안은 주제 범위의 가설로만 저장합니다.
4. 원문 인용·종류·범위를 검증한 항목은 자동 저장합니다. 모델 답변에서 등록한 맥락은 다음 질문부터 사용합니다.

선택·추출에 질문마다 최대 2회 추가 호출합니다. 자동 선택 시 후보들의 내용을, 추출 시 분석 대상 원문과 기존 저장 항목을 연결된 모델에 전달합니다. 클라우드 연결이면 이 입력도 제공자에게 전송합니다. 호출별 실제 본문·결과·사용량은 답변 기록에서 볼 수 있습니다. 모델의 선택 이유는 설명이며 선택 정확도가 보장된다는 뜻은 아닙니다.

선택 결과가 누락·중복·잘못된 ID 등으로 검증에 실패하면 태그·수동 선택으로 돌아가며 경고를 표시합니다. 추출 실패는 답변을 버리지 않고 경고와 실패한 입력·결과를 보존합니다. 시연 모드는 자동 선택·추출을 수행하지 않습니다. 자동 관리를 끄면 기존 태그 기준으로 동작합니다.

## 수동 컨텍스트 관리

- 제목·내용·종류(배경/참고/가설), 프로젝트 또는 주제 범위, 포함 방식을 지정합니다.
- ‘범위·주제에 따라 선택’은 질문의 의미와 자동으로 판단한 주제를 기준으로 선택합니다. ‘항상 포함’은 해당 프로젝트 모든 대화에 포함하고, ‘기본 포함 꺼짐’은 자동 선택에서 제외합니다.
- 대화별로 직접 포함하거나 제외할 수 있습니다. 이 선택은 다른 대화에 영향을 주지 않으며, 편집 후 새 버전에도 이어집니다.
- 가설과 참고 자료는 모델 입력에서 종류를 표시하고 확정된 사실로 취급하지 않도록 지시합니다.
- 편집하면 새 버전을 추가하고 과거 버전을 보존합니다. 보관된 컨텍스트는 직접 포함 선택이 있어도 제외하며, 다시 사용할 수 있습니다.
- 메시지의 ‘컨텍스트로 저장’으로 원문을 연결할 수 있습니다. 편집한 내용은 별도 버전으로 보존하고 원문을 바꾸지 않습니다. 일반적인 대화에서는 별도 저장 버튼 없이 자동 등록됩니다.
- 컨텍스트로 저장한 원문은 최근 대화에서 자동으로 중복 주입하지 않습니다. 제외한 자료가 자동 대화 이력을 통해 다시 들어오는 것을 방지합니다.
- 저장·편집·보관·대화별 선택은 이후 호출에 적용합니다. 과거 답변에 전달된 버전·내용·선택 이유는 변경하지 않습니다.

## 모델 연결

OAuth는 로컬 앱에서 ChatGPT 모델 호출을 인증하는 선택 연결입니다. 컨텍스트를 만들거나 저장하는 로그인 수단은 아닙니다. 연결을 끊어도 프로젝트·대화·저장된 컨텍스트는 로컬 DB에 남습니다. 공개 데모는 ChatGPT OAuth를 사용하지 않고 로그인 없이 시연 모드로 열리며, 실제 모델 답변은 방문자 본인의 API 키가 있을 때만 호출합니다.

### ChatGPT OAuth

**Continue with ChatGPT** → 공식 인증 페이지에서 권한 승인 → 이 앱의 `/auth/callback`으로 돌아오는 흐름입니다. PKCE, state, nonce, ID 토큰 서명·issuer·audience·만료·계정 일치, 플랜 사용 scope를 확인한 뒤 인증을 저장합니다.

로그인 창이 열리면 앱에서 대기 상태와 취소 버튼을 표시합니다. 팝업이 차단된 경우 **이 탭에서 로그인 계속**을 사용할 수 있습니다. 로그인 완료 후 원래 앱은 연결 결과와 해당 계정의 모델 목록을 자동으로 확인합니다. **이 계정에서 사용할 모델**을 고르고 **이 모델로 채팅 시작**을 누르세요. 첫 연결에는 플랜 사용 안내가 한 번 표시됩니다. 모델 ID는 계정의 실제 목록에서 선택하며 특정 모델에 대한 이용 권한을 가정하지 않습니다. OAuth는 기존 ChatGPT 대화 접근을 제공하지 않습니다. 플랜 사용 가능 여부는 계정·워크스페이스·제공자 정책에 따릅니다.

저장된 계정의 선택·재연결, 로그인 취소·만료·실패 상태, 계정별 토큰 갱신, 원격 세션 해제, 서명·원문 요청 검증 테스트를 구현했습니다. 계정이 같아도 워크스페이스별 등록은 분리합니다. 로그인만 승인하고 플랜 사용을 승인하지 않은 계정은 모델 호출을 막으며 **플랜 사용 권한 승인**으로 다시 승인할 수 있습니다. 연결 해제는 원격 갱신 세션의 해제를 시도하고 로컬 토큰을 삭제합니다. 원격 해제를 확인하지 못하면 그 상태를 표시합니다. 등록·호스트 식별자는 재연결에 유지합니다. 앱을 `localhost`로 열면 OAuth 쿠키와 콜백이 같은 호스트를 사용하도록 `127.0.0.1`로 이동합니다. 진행 중인 모델 요청에는 시작 시 선택한 계정이 유지됩니다.

대체 인증 서버와 서명된 테스트 토큰으로 브라우저의 로그인 대기 → 콜백 → 모델 목록 → 채팅 설정 → 연결 해제·취소 흐름을 확인했습니다. 이 작업에서 사용자의 실제 계정 로그인·플랜 추론은 실행하지 않았습니다. 실제 연결은 사용자가 앱에서 로그인한 뒤 확인해야 합니다.

### OpenAI API 키

연결 방식을 **OpenAI API 키**로 선택하고 키를 입력합니다. **모델 목록·연결 확인**으로 목록을 조회한 후 텍스트 Responses API를 지원하는 모델을 선택하고 저장하세요. 사용자의 API 계정으로 모델 호출 비용이 발생할 수 있습니다. 실제 키로 과금 요청을 실행하지 않았습니다.

### 로컬 Ollama / Gemma

이미 실행 중인 Ollama의 주소(기본 `http://127.0.0.1:11434`)를 지정하고 모델 목록을 조회합니다. 설치된 Gemma 등의 모델 이름을 선택한 뒤 저장하세요. 앱이 모델 설치나 다운로드를 자동 수행하지 않습니다.

연결 코드는 `/api/tags`와 `/api/chat`을 사용합니다. 이 작업에서 실제 로컬 모델 추론은 실행하지 않았습니다. UI 폰트와 아이콘은 Google Fonts에서 불러오므로 첫 화면의 외부 자산 요청까지 완전히 오프라인인 앱은 아닙니다. 앱 스타일과 자바스크립트는 로컬에서 제공합니다.

## 현재 구현 범위

- 프로젝트 생성·선택, 대화 생성·선택, 원문 메시지 저장
- 대화 원문에서 파악한 내용의 자동 등록과 원문 근거 추적
- 컨텍스트 등록·편집·버전 이력·보관/복원·검색·종류/상태 필터
- 모델을 통한 질문별 주제 추출·컨텍스트 의미 선택, 태그 기준 대체 처리
- 사용자 발화·모델 응답 기반 자동 등록, 모델 제안의 가설 구분
- 주제 기반 컨텍스트 선택과 대화별 수동 포함·제외·자동 선택 복원
- 현재 주제와 관련된 저장 컨텍스트 및 최근 메시지 선택
- ChatGPT OAuth 로그인·계정 선택·재연결·취소·권한 상태·자동 모델 목록·갱신·세션 해제
- 생성 → 원문 기반 검증 → 교정 최대 1회 → 재검증 1회
- 검증자가 인용한 원문·초안 문구가 실제 입력과 일치하는지 확인
- 근거 불일치·검증 형식 오류는 판단 보류, 재검증 충돌은 미해결, 호출 실패는 실패로 구분
- 호출 입력을 전송 전에 직렬화하여 SQLite에 저장하고 같은 문자열을 HTTP 본문으로 전달
- 인증 헤더를 제외한 전체 본문·모델·단계·hash·결과·보고된 토큰 사용량·지연 기록
- 호출별/답변 간 컨텍스트 블록 비교, 원문 근거 조회
- 실제 대화·컨텍스트·호출 데이터 JSON 및 SQLite 다운로드. 인증 정보는 제외

자동 관리에서 모델이 질문의 주제와 관련 저장 항목을 고릅니다. 추출 범위는 최근 사용자 발화 8개, 수동 분석은 24개입니다. 임베딩 검색, 긴 기록 전체를 검색하는 에이전트, 외부 앱 대화 가져오기, 데이터 가져오기·삭제는 아직 구현하지 않았습니다. 대화에서 파악한 내용은 검증과 답변 영수증의 원문 근거로 사용됩니다.

검증 모델은 생성 모델과 별도 호출이지만 같은 모델을 사용합니다. 독립된 모델 선택과 검증 성능 평가는 후속 범위입니다. 시연은 오류 처리 흐름의 검증이며 탐지 정확도 벤치마크가 아닙니다.

## 저장 데이터

기본 저장 위치는 `data/`입니다.

- `contextpulse.sqlite`: 프로젝트, 대화 원문, 컨텍스트·자동 등록 후보, 답변 처리 기록, 호출 스냅샷, 모델 설정
- `credentials.json`: 사용자 계정 등록·OAuth 자격 증명·선택적 API 키·호스트 ID

인증 파일은 서버에서만 읽고 생성 권한을 `0600`으로 제한합니다. OS 키체인/암호화 연동은 아직 제공하지 않습니다. 이 파일과 `data/`를 공유하거나 저장소에 커밋하지 마세요. 내보내기에는 인증 파일이 포함되지 않습니다. 로컬 저장 자체가 디스크 암호화를 의미하지 않습니다.

호출 스냅샷은 앱의 UPDATE/DELETE 방지 규칙으로 보존합니다. 사용자에게 디스크 파일을 직접 수정할 권한이 있으므로 위변조 방지 보관소나 법적 감사 인증을 의미하지 않습니다. 새 요청은 새 호출 기록을 추가합니다.

## 개발과 검증

```sh
npm test
npm ci
npm run build:css
```

테스트는 별도 임시 디렉터리를 사용하고 사용자 대화나 인증 파일을 읽지 않습니다. 실제 과금 모델을 호출하지 않으며, 네트워크 응답을 대체하여 의미 선택 결과 적용·원문 후보 확인·중복 방지·요청 본문 보존·오류·교정 제한·원문 검증·인증 검증을 확인합니다.

서버는 Node 기본 HTTP와 SQLite 기능을 사용하므로 런타임 외부 의존성이 없습니다. Tailwind는 스타일 재생성을 위한 개발 의존성입니다.

## 공개 데모 서버와 Cloudflare

`docker compose -f compose.yaml up -d --build` 후 `http://127.0.0.1:8903`에서 공개 데모 모드를 로컬 테스트합니다. 기존 로컬 대화·OAuth 계정과 다른 저장소를 사용하고 방문자별 DB·API 키를 분리합니다. 기본 시연 모드 또는 방문자 본인의 API 키를 지원하며, ChatGPT OAuth는 로컬 앱에서 유지합니다.

배포는 영구 저장소가 있는 Node 서버를 Cloudflare Tunnel로 연결하는 구성입니다. Workers만 사용하는 배포는 아닙니다. 공개 연결은 아직 실행하지 않았습니다. [배포·검증 안내](docs/cloudflare-demo.md)를 참고하세요.
