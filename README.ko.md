# ContextPulse

질문마다 필요한 컨텍스트를 자동으로 선택하고, 모델에 실제로 전달한 내용을 답변별로 보여주는 로컬 웹 채팅 프로토타입입니다. 메뉴를 채팅·컨텍스트 관리·답변 기록·설정으로 정리하고, 대화에 필요한 정보 선택과 실제 입력 기록에 집중했습니다.

현재 제품 범위와 심사 데모 흐름은 [프로젝트 정리 문서](docs/project-summary.md)에서 확인할 수 있습니다.
Colosseum 제출 항목과 공개 전 체크리스트는 [제출 준비 문서](docs/submission-readiness.md)에 정리했습니다.

## 실행

Node.js 24 이상에서 실행합니다. 실행 시 외부 패키지 설치가 필요하지 않습니다. 생성된 스타일 파일을 포함합니다.

```sh
npm start
```

브라우저에서 <http://127.0.0.1:8899>를 엽니다. 서버는 `127.0.0.1`에만 바인딩됩니다.

포트 또는 저장 위치를 변경할 수 있습니다.

```sh
CONTEXTPULSE_PORT=8900 CONTEXTPULSE_DATA_DIR=./my-data npm start
```

앱 종료는 실행한 터미널에서 Ctrl+C를 누릅니다. 다시 실행하면 저장한 대화·컨텍스트·호출 기록을 불러옵니다.

## 첫 사용

1. **교정 흐름 시연**을 누르면 별도 프로젝트에 대화 맥락과 어긋난 초안, 원문 확인, 교정, 재검증 기록을 만듭니다. 실제 모델 호출은 없습니다.
2. 왼쪽 아래의 **ChatGPT 로그인**을 한 번 누르고 공식 로그인과 권한 승인을 마칩니다. 모델은 채팅 입력창에서 고릅니다.
3. **프로젝트 채팅**에서 메시지만 보냅니다. 에이전트가 주제와 필요한 컨텍스트를 자동으로 판단합니다.
4. **컨텍스트 관리**에서 배경 정보·참고 자료·검토 중인 가설을 관리하고, 별도 탭에서 대화의 기준과 원문 근거를 확인하거나 보관·복원·삭제합니다.
5. 사용자 발화와 모델 답변에서 맥락을 자동 등록합니다. 저장 버튼을 누를 필요가 없습니다. 원문과 추출 입력·결과를 확인하고 필요하면 컨텍스트를 편집·보관합니다.
6. 채팅 우측에서 최근 답변에 실제 사용한 맥락과 자동 선택 결과를 확인합니다. 대화별 포함·제외 선택은 저장됩니다.
7. 답변별 영수증에서 자동 주제, 저장 맥락, 대화에서 파악한 내용, 이전 대화와 원문을 확인합니다.
8. 답변의 **교정 과정·컨텍스트 보기**에서 각 호출의 입력·결과·출처·RAW를 확인합니다. **입력 차이 비교**로 초안/교정 또는 이전 답변의 호출을 비교할 수 있습니다.

## 자동 컨텍스트 관리

설정의 **대화 맥락 자동 등록·SQLite FTS5 검색**은 기본적으로 켜져 있습니다. 주제는 모델이 파악하고, 저장 컨텍스트 검색은 SQLite FTS5가 키워드 일치 점수와 기준값으로 처리합니다.

1. 질문과 짧은 이전 대화에서 주제를 파악합니다. 저장 컨텍스트의 제목·내용·주제는 SQLite FTS5로 검색하고, 키워드·주제 일치 점수가 기준 이상인 항목을 최대 8개까지 선택합니다. 직접 포함·제외한 선택과 항상 포함 항목은 유지합니다. 이전 대화의 자동 분류 기록을 이용해 관련 발화만 이어받습니다.
2. 선택 결과로 답변 입력을 구성하고 기존 생성·검증·교정 흐름을 수행합니다.
3. 답변을 만든 뒤 최근 대화 최대 8턴의 사용자 발화와 모델 답변에서 유용한 맥락을 추출합니다. 사용자 원문에서 나온 맥락은 자동 등록합니다. 모델 답변의 제안은 주제 범위의 가설 후보로 남겨 승인 전에는 이후 답변에 전달하지 않습니다.
4. 새로 등록한 맥락은 다음 관련 질문부터 선택합니다. 사용자가 대화에서 명시적으로 고친 기준은 현재 답변에도 즉시 반영합니다.

주제 분석·추출에 질문마다 최대 2회 추가 호출합니다. 저장 컨텍스트 전체를 검색하기 위해 모델에 보내지 않습니다. 주제 분석에는 현재 질문과 짧은 이전 대화를, 추출에는 분석 대상 원문과 기존 저장 항목을 연결된 모델에 전달합니다. 클라우드 연결이면 이 입력도 제공자에게 전송합니다. 호출별 실제 본문·결과·사용량은 답변 기록에서 볼 수 있습니다. 검색 점수와 기준은 답변 영수증에 표시합니다.

검색 점수는 질문 키워드와 저장 컨텍스트의 일치율에 주제 일치 점수를 더해 계산하고, SQLite FTS5 BM25 순위로 정리합니다. 임베딩이나 의미 검색은 사용하지 않으므로 동의어나 겹치는 키워드가 없는 바꿔 말하기는 관련 컨텍스트를 찾지 못할 수 있습니다. 실제 검색어, 점수, 기준, 전달된 컨텍스트는 답변 영수증에 보존됩니다.

주제 분석 결과가 잘못되면 태그·수동 선택을 사용하고 경고를 표시합니다. 추출 실패는 답변을 버리지 않고 경고와 실패한 입력·결과를 보존합니다. 시연 모드는 자동 선택·추출을 수행하지 않습니다. 자동 관리를 끄면 기존 태그 기준으로 동작합니다.

## 수동 컨텍스트 관리

- 제목·내용·종류(배경/참고/가설), 프로젝트 또는 주제 범위, 포함 방식을 지정합니다.
- ‘범위·주제에 따라 선택’은 SQLite FTS5 키워드·주제 점수가 기준 이상이면 포함합니다. ‘항상 포함’은 해당 프로젝트 모든 대화에 포함하고, ‘기본 포함 꺼짐’은 자동 검색에서 제외합니다.
- 대화별로 직접 포함하거나 제외할 수 있습니다. 이 선택은 다른 대화에 영향을 주지 않으며, 편집 후 새 버전에도 이어집니다.
- 가설과 참고 자료는 모델 입력에서 종류를 표시하고 확정된 사실로 취급하지 않도록 지시합니다.
- 편집하면 새 버전을 추가하고 과거 버전을 보존합니다. 보관된 컨텍스트는 직접 포함 선택이 있어도 제외하며, 다시 사용할 수 있습니다. 삭제하면 해당 컨텍스트의 모든 버전과 검색 항목을 제거하고, 과거 답변의 실제 전달 기록은 유지합니다.
- 컨텍스트를 직접 보완하려면 컨텍스트 관리에서 추가·편집합니다. 일반 대화에서 유용한 내용은 답변 뒤 원문과 함께 자동 등록되며 메시지별 저장 버튼은 없습니다.
- 사용자 발화에서 나온 기준은 별도 탭에서 원문을 확인하고 보관·복원·삭제할 수 있습니다. 모델이 제안한 가설은 자동 등록 이력에 바로 확정하지 않고 검토 대기 목록에서 승인하거나 무시합니다.
- 컨텍스트로 저장한 원문은 최근 대화에서 자동으로 중복 주입하지 않습니다. 제외한 자료가 자동 대화 이력을 통해 다시 들어오는 것을 방지합니다.
- 저장·편집·보관·대화별 선택은 이후 호출에 적용합니다. 과거 답변에 전달된 버전·내용·선택 이유는 변경하지 않습니다.

## 모델 연결

왼쪽 아래에서 ChatGPT에 한 번 로그인하고, 채팅 입력창에서 계정이 사용할 수 있는 모델을 선택합니다. 모든 대화에서 같은 ChatGPT 연결을 사용합니다. 로그인은 모델 답변 생성에만 필요하며 대화·컨텍스트는 앱에서 관리합니다. 기존 ChatGPT 대화 기록은 가져오지 않습니다. 컨텍스트 선택·추출·검증·교정도 연결한 ChatGPT 플랜의 추가 요청을 사용할 수 있습니다.

### ChatGPT OAuth

**Continue with ChatGPT** → 공식 인증 페이지에서 권한 승인 → 이 앱의 `/auth/callback`으로 돌아오는 흐름입니다. PKCE, state, nonce, ID 토큰 서명·issuer·audience·만료·계정 일치, 플랜 사용 scope를 확인한 뒤 인증을 저장합니다.

로그인 창에서 권한을 승인하면 앱이 연결 상태와 모델 목록을 확인합니다. 채팅 입력창에서 사용할 모델을 고르면 대화를 시작할 수 있습니다. 첫 연결에는 플랜 사용 안내가 한 번 표시됩니다. 모델 목록은 계정에서 실제로 사용 가능한 항목을 기준으로 합니다. 플랜 사용 가능 여부는 계정·워크스페이스·제공자 정책에 따릅니다.

로그인 취소·만료·실패 상태, 계정별 토큰 갱신, 세션 해제, 서명·원문 요청 검증을 구현했습니다. ChatGPT 인증은 워크스페이스별로 저장합니다. 로그아웃하면 로컬 토큰을 제거하며, 진행 중인 모델 요청은 시작 시 연결한 계정을 유지합니다. 앱을 `localhost`로 열면 OAuth 쿠키와 콜백이 같은 호스트를 사용하도록 `127.0.0.1`로 이동합니다.

대체 인증 서버와 서명된 테스트 토큰으로 브라우저의 로그인 대기 → 콜백 → 모델 목록 → 채팅 설정 → 연결 해제·취소 흐름을 확인했습니다. 이 작업에서 사용자의 실제 계정 로그인·플랜 추론은 실행하지 않았습니다. 실제 연결은 사용자가 앱에서 로그인한 뒤 확인해야 합니다.

오픈소스 OAuth 연결은 `127.0.0.1` 루프백 콜백을 사용합니다. 따라서 로컬 `127.0.0.1:8899`와 로컬 hosted-mode 테스트 `127.0.0.1:8903`에서는 같은 ChatGPT 로그인 기능을 사용할 수 있습니다. 공개 HTTPS 웹사이트에서 OAuth를 쓰려면 OpenAI에 웹 로그인 클라이언트와 공개 콜백 주소를 등록해야 합니다. 이 승인이 끝나기 전에는 공개 주소에서 실제 모델 연결을 활성화할 수 없습니다. 자세한 내용은 [OpenAI 웹 로그인 안내](https://developers.openai.com/siwc/website)를 참고하세요.

## 현재 구현 범위

- 프로젝트 생성·선택, 대화 생성·선택, 원문 메시지 저장
- 사용자 발화에서 파악한 내용의 자동 등록과 원문 근거 추적
- 모델 답변에서 제안한 가설의 승인·무시 검토 대기열
- 대화 기준의 원문 보기, 보관·복원·삭제와 대체 버전 이력
- 컨텍스트 등록·편집·버전 이력·보관/복원·삭제·검색·종류/상태 필터
- 개별 대화 삭제와 해당 대화에서 나온 컨텍스트·기준·답변·호출 기록 정리. 마지막 대화 삭제 시 빈 대화를 자동 생성
- 모델을 통한 질문별 주제 추출, SQLite FTS5 키워드 점수 기반 컨텍스트 검색, 태그 기준 대체 처리
- 사용자 발화·모델 응답 기반 자동 등록, 모델 제안의 가설 구분
- 주제 기반 컨텍스트 선택과 대화별 수동 포함·제외·자동 선택 복원
- 현재 주제와 관련된 저장 컨텍스트 및 최근 메시지 선택
- ChatGPT OAuth 로그인·취소·권한 상태·자동 모델 목록·토큰 갱신·세션 해제
- 생성 → 원문 기반 검증 → 교정 최대 1회 → 재검증 1회
- 검증자가 인용한 원문·초안 문구가 실제 입력과 일치하는지 확인
- 근거 불일치·검증 형식 오류는 판단 보류, 재검증 충돌은 미해결, 호출 실패는 실패로 구분
- 호출 입력을 전송 전에 직렬화하여 SQLite에 저장하고 같은 문자열을 HTTP 본문으로 전달
- 인증 헤더를 제외한 전체 본문·모델·단계·hash·결과·보고된 토큰 사용량·지연 기록
- 호출별/답변 간 컨텍스트 블록 비교, 원문 근거 조회
- 실제 대화·컨텍스트·호출 데이터 JSON 및 SQLite 다운로드. 인증 정보는 제외
- 설정에서 저장소의 프로젝트·대화·컨텍스트·결정·답변·호출 기록 전체 삭제. 로그인과 앱 설정은 유지
- 사용자 발화 언어와 요청 항목 수에 맞는 답변 생성 및 감지 가능한 형식 오류 1회 교정

자동 관리에서 모델이 질문 주제를 파악하고 SQLite FTS5가 점수 기준으로 관련 저장 항목을 고릅니다. 추출 범위는 최근 사용자 발화 8개, 수동 분석은 24개입니다. 임베딩 검색, 긴 기록 전체를 검색하는 에이전트, 외부 앱 대화 가져오기와 데이터 가져오기는 아직 구현하지 않았습니다. 설정에서 전체 저장소를 비우거나 개별 대화를 삭제할 수 있습니다. 개별 컨텍스트와 대화 기준도 삭제할 수 있으며, 과거 답변의 실제 전달 기록은 보존됩니다. 대화에서 파악한 내용은 검증과 답변 영수증의 원문 근거로 사용됩니다.

검증 모델은 생성 모델과 별도 호출이지만 같은 모델을 사용합니다. 독립된 모델 선택과 검증 성능 평가는 후속 범위입니다. 시연은 오류 처리 흐름의 검증이며 탐지 정확도 벤치마크가 아닙니다.

## 저장 데이터

기본 저장 위치는 `data/`입니다.

- `contextpulse.sqlite`: 프로젝트, 대화 원문, 컨텍스트·자동 등록 후보, 답변 처리 기록, 호출 스냅샷, 모델 설정
- `credentials.json`: OAuth 자격 증명과 호스트 ID

인증 파일은 서버에서만 읽고 생성 권한을 `0600`으로 제한합니다. OS 키체인/암호화 연동은 아직 제공하지 않습니다. 이 파일과 `data/`를 공유하거나 저장소에 커밋하지 마세요. 내보내기에는 인증 파일이 포함되지 않습니다. 로컬 저장 자체가 디스크 암호화를 의미하지 않습니다.

호출 스냅샷은 앱의 UPDATE/DELETE 방지 규칙으로 보존합니다. 사용자에게 디스크 파일을 직접 수정할 권한이 있으므로 위변조 방지 보관소나 법적 감사 인증을 의미하지 않습니다. 새 요청은 새 호출 기록을 추가합니다.

## 개발과 검증

```sh
npm test
npm ci
npm run build:css
```

테스트는 별도 임시 디렉터리를 사용하고 사용자 대화나 인증 파일을 읽지 않습니다. 실제 과금 모델을 호출하지 않으며, 네트워크 응답을 대체하여 FTS5 검색 점수·임계값·다중 컨텍스트 전달·프로젝트 격리·원문 후보 확인·중복 방지·요청 본문 보존·오류·교정 제한·인증 검증을 확인합니다.

서버는 Node 기본 HTTP와 SQLite 기능을 사용하므로 런타임 외부 의존성이 없습니다. Tailwind는 스타일 재생성을 위한 개발 의존성입니다.

## 답변별 컨텍스트 확인

답변 아래의 ‘이번 답변에 전달한 컨텍스트’에서 자동 주제, 저장 맥락, 대화에서 파악한 내용, 이전 대화 수를 확인합니다. 펼치면 내용·선택 이유·원문을 볼 수 있습니다. 현재 저장된 최신 버전이 아니라 답변 당시의 불변 요청 기록을 표시합니다. 영어 기본 화면과 `/ko/`는 같은 기록을 공유하며, 진행·완료 안내는 선택한 언어로 표시합니다.

## 공개 데모 서버와 Cloudflare

`docker compose -f compose.yaml up -d --build` 후 `http://127.0.0.1:8903`에서 hosted-mode 앱을 로컬 테스트합니다. 일반 채팅, ChatGPT OAuth, 입력창 모델 선택, 자동 컨텍스트 기능이 로컬 앱과 동일하게 동작하며, 저장소는 방문자별로 분리됩니다. 이 테스트 주소는 loopback이므로 OpenAI 오픈소스 OAuth 콜백을 사용할 수 있습니다. 공개 HTTPS 사이트에서는 별도로 등록된 OpenAI 웹 로그인 콜백이 필요합니다. 승인 전에는 공개 주소를 실제 모델 사용이 가능한 데모로 공개하지 않습니다.

배포는 영구 저장소가 있는 Node 서버를 Cloudflare Tunnel로 연결하는 구성입니다. Workers만 사용하는 배포는 아닙니다. 공개 연결은 아직 실행하지 않았습니다. [배포·검증 안내](docs/cloudflare-demo.md)를 참고하세요.
